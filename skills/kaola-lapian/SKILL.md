# Kaola 视频拉片

把用户有权分析的视频转换成可复核的时间轴资料。先忠实提取，再按用户目的路由；不要在基础拉片阶段优化文案、替换卖点或改写原片结构。

## 先确定任务

确认以下信息；能从链接和文件直接读取的不要重复询问：

1. 输入是公开视频链接还是本地视频。
2. 输出用途：`基础拉片`、`带货输入`、`复刻输入`，可以同时选择后两者。
3. 抽帧间隔。用户未指定时用每秒一帧；动作密集或切换极快处在初检后加密到每 0.25–0.5 秒一帧。
4. 用户是否拥有下载、分析和后续使用该视频的权利。只做分析不等于获得复刻、发布或商业使用授权。

## 获取视频与页面信息

对链接先读取页面可见内容，提取：原始链接、平台、作品 ID、作者、标题、发布时间和标题中的 Hashtag。Tag 只取作者标题明确写出的 `#标签`；搜索联想、评论、推荐视频和页面导航不算原视频 Tag。

优先使用浏览器已观察到的真实视频资源或平台允许的下载方式保存源视频。不要读取浏览器 Cookie、Local Storage、密码或私密会话数据，也不要调用来源不明的去水印站。若页面只允许播放但无法安全保存，请用户上传本地文件或提供可访问直链。

每个视频使用独立项目目录：

```text
<output>/<platform>-<作品ID或文件名>/
├── source.mp4
├── page-metadata.json
├── video-info.json
├── audio.wav
├── frames/
├── frames.json
├── storyboard-grid.jpg
├── storyboard-order.json
├── storyboard-order.md
├── storyboard-script-grid.jpg
├── storyboard-script-order.json
├── transcript.json
├── lapian-base.md
├── route-daihuo.md        # 按需
└── route-fuke.md          # 按需
```

所有路径使用相对路径记录；不要覆盖其他项目。

## 本地抽帧

先检查 FFmpeg 与 FFprobe。运行：

```bash
python3 scripts/extract_timeline.py <source.mp4> --output <项目目录> --interval 1
```

该脚本读取真实时长、分辨率、帧率和音轨，抽取每秒一帧、生成时间码清单、六列分镜图和 16 kHz 单声道 WAV。分镜固定按从左到右、每行六张、排满换行的顺序展示；每格顶部标注分镜序号和时间码。视频太长导致单张图片超过安全高度时允许拆成多个连续分页，但全局序号继续递增，不能丢帧或在新页重新编号。

同时生成 `storyboard-order.json` 和 `storyboard-order.md`，逐张记录全局顺序、行、列、页码、时间码和对应图片路径。交付分镜图时必须同时交付顺序文件；不要让用户仅凭文件名猜排列。

一秒一帧只是全片索引，不等于镜头切点。检查长图后，对以下位置补抽帧：硬切前后、手部操作、商品翻转、遮挡、人物交互、快速推拉摇移、开头与结尾。不要用稀疏帧补造看不到的中间动作。

## SenseVoice Small 转写

先运行探测：

```bash
python3 scripts/transcribe_sensevoice.py --check
```

默认本地模型为 `iic/SenseVoiceSmall`，设备默认 `cpu`，语言默认自动识别，开启 ITN，并组合 `fsmn-vad` 获得长音频分段。执行：

```bash
python3 scripts/transcribe_sensevoice.py <项目目录>/audio.wav --output <项目目录>/transcript.json
```

如果当前 Python 找不到 `funasr` 或 `torch`，明确报告“当前环境未就绪”；不要声称模型已安装。允许用户确认后在项目外的独立虚拟环境部署，或使用用户已有的 SenseVoice 可执行程序。不要把模型权重、虚拟环境或密钥打包进 Skill。

SenseVoice 输出是转写草稿，不是最终台词：去掉语言、情绪和事件标签，保留原意；结合音频复核品牌名、数字、同音字、口头停顿和背景音乐干扰。连续口播优先把“整段识别”作为词句主稿，把按镜头短切后的识别只作为时间对齐提示；短切可能从词中间截断，不能用它覆盖更完整的整段结果。无语音区写空脚本，不把音乐、评论或画面文字当成人声。

## 对齐画面与脚本

按真实镜头切换和语义完整性划分时间段，不机械地每秒生成一条。每段同时满足：

- 画面主体、场景或主动作相对连续；
- 台词尽量保持完整短句；
- 时间连续、无重叠、无空档，首段从 `0:00` 开始，末段到真实时长；
- `画面`只描述实际可见内容，包括主体、动作、场景、景别和必要运镜；不写卖点评价；
- `脚本`来自实际语音转写，无语音时写 `无`；不因画面文字相似就补造台词。

输出前逐段回看原片，并对照抽帧与转写。对不确定内容使用 `[听辨不清]`、`[画面待复核]`，不要猜。

## 生成图文分镜图

完成并复核 `lapian-base.md` 后，必须再生成第二张图文分镜图：

```bash
python3 scripts/render_script_storyboard.py <项目目录> --timeline <项目目录>/lapian-base.md --columns 6
```

两张分镜图必须同时交付：

1. `storyboard-grid.jpg`：保持逐秒纯画面索引，每格只显示分镜序号、帧时间码和图片。
2. `storyboard-script-grid.jpg`：使用与第一张完全相同的逐秒帧、全局序号和六列顺序；在每张图片下方写出该帧所在拉片段的 `时间`、`画面`、`脚本`。

图文分镜不得重新选镜、删帧或改变排列。某个拉片段覆盖多个逐秒帧时，允许这些帧重复显示同一组时间、画面和脚本，以保证两张图可以逐格对照。以帧时间码落入 `开始时间 ≤ 帧时间 < 结束时间` 的规则匹配拉片段；末帧可匹配最后一段。脚本改动后必须重新运行该脚本，不能交付与 `lapian-base.md` 不一致的旧图。

同时生成 `storyboard-script-order.json`，记录每格的全局顺序、行列、页码、帧时间码、原图路径、对应拉片段、时间、画面和脚本。视频过长而触发安全分页时，纯画面图和图文图都保持全局编号连续，并交付全部分页。

## 路由输出

读取 [output-contracts.md](references/output-contracts.md)，严格使用对应结构。

### 基础拉片 / 带货输入

交付标题、Tag、来源信息、视频规格，以及只有以下三项的逐段主体：

```text
时间: "0:00-0:02"
画面: "……"
脚本: "……"
```

基础拉片保持原文原画，不自动补音乐、音效、卖点大字或生成约束。用户随后要制作新带货视频时，把这份材料交给 `kaola-daihuo`；由后者重新确认发布平台、TikTok 市场与语言、卖点、时长、画幅、模型、分辨率及声音选项。

### 复刻输入

保留基础拉片，并额外给出：镜头编号、精确起止时间、切换方式、景别、构图、机位、镜头运动、人物与物体、逐步动作、遮挡关系、原声状态、必须锁定项和风险。把 `source.mp4` 标记为 `@视频1 = 结构底片`。

用户未提供“原元素 → 新元素”映射时，只输出结构分析并列为待补输入，不擅自决定换什么。随后把这份材料交给 `kaola-fuke` 生成替换映射、逐段策略和提示词。

## 质检

交付前检查：

1. 源视频可解码，时长、分辨率、帧率和音轨已记录。
2. 抽帧数量与时长、间隔相符；纯画面图和图文图使用相同帧数、相同全局序号，均从左到右、每行六张，顺序清单没有错序或漏图。
3. 标题和 Tag 来自作品标题，不混入评论与推荐内容。
4. 转写覆盖全部语音区，品牌名、数字和专有名词已标记或复核。
5. 时间轴连续；画面描述与对应时刻一致；未把一秒静帧当成完整动作证据。
6. 图文分镜每格的时间、画面和脚本均来自最新版 `lapian-base.md`，与该帧所处时间段一致，没有串段、截断或旧稿残留。
7. 带货路由未提前优化；复刻路由包含结构锁定信息，且没有虚构替换目标。

## 固定交付

1. **来源与规格**。
2. **标题与 Tag**。
3. **两张六列分镜图**：纯画面分镜图，以及图片下带时间、画面、脚本的图文分镜图；同时交付两份顺序数据和逐秒帧目录。
4. **SenseVoice 状态与转写说明**。
5. **基础拉片：时间 / 画面 / 脚本**。
6. **带货或复刻路由文件**（按用户选择）。
7. **不确定项与质检结果**。
