# 安全与执行约束


## 隐私与密钥

- 不把 API key、令牌或完整凭据写入 Skill、代码示例、提示词、任务记录或交付文档。
- 只从环境变量、本机安全配置或受控密钥存储读取凭据。
- 上传私密人脸、内部产品或未发布素材到第三方前，确认用户允许该外部处理。
- H3 原生台词模式只调用 MiniMax-H3 视频生成 API，由视频模型同步生成人声与口型；不得调用 TTS、音色合成、声音克隆、配音或其他独立音频 API，不得传入 `reference-audio`。
- 公网临时链接可能可被持链访问且会过期。记录过期时间，生成完成后立即下载，并避免在公开消息中传播。

## 外部生成

- 只有用户明确要求实际生成时才调用付费或会创建远程任务的接口。方案与提示词请求不自动触发付费生成。
- H3 原生台词模式下，每一次付费视频生成或重试前都必须核对当前版本的声音确认单。准确台词、语言、说话人性别表现与年龄感、语气和节奏任一项未获用户明确确认时，不得提交。
- 语言默认沿用原片识别语言，但“默认沿用”不能替代用户确认；说话人表现依据原片人物和替换人物参考推断，不得使用“年轻女性”或任何固定人口特征作为通用默认。
- 用户要求修改特效时，付费生成前必须确认带时间码的“原特效 → 新特效”变更表；任何待确认项都必须停在执行包。
- 默认在提示词中抑制自动字幕，但不因准确字幕自动发起付费重试。用户未明确要求无字幕时，与确认台词逐字一致、同步稳定且不遮挡主体的 H3 字幕可验收；用户明确要求无字幕时，任何字幕都必须判失败并只修问题段。
- 静态图像生成或编辑默认使用系统内置图片能力；只在生成新的虚构人脸参考图时建议 GPT Image Two，未配置时直接回退到内置能力。视频生成或编辑默认使用 `MiniMax-H3`，请求 `768P` 档。
- 使用 H3 的参考视频能力保留输入视频结构。纯文生视频不能当作严格复刻工具。
- H3 的台词条件可能连带改变镜头运动和物理动作。H3 原生台词模式仍默认保留同一次生成的画面与音轨，但必须把无口型产品/手部/B-roll 按单一物理动作切短，用动作正确底片和逐时间状态链控制。一次针对性重试仍失败时停止付费；只有用户明确同意，才使用锁定画面并只取 H3 视频 API 原生音轨的回退方案。
- 供应商模型名、接口、时长和参数会变化；执行前检查当前工具，不照抄旧接口说明。
- 不得静默切换备用模型。默认模型不可用或一次针对性重试仍失败时，报告问题并等待用户指定其他模型或接受本地回退。
- 先用最难的一个短段验证一致性，再批量提交。设置有限重试次数，保存每次失败原因。
- 只向每个任务上传必要素材，减少隐私暴露和参考污染。

## 媒体准备

- 保持原片画幅。检查视频与音轨均可读取；存在 H3 生成段时默认使用 `768P` 档，并把所有片段统一到同一最终画布。
- 把复杂混合镜头切成按动作或镜头角色划分的短段。H3 参考视频须为 2–15 秒，生成时长须为 4–15 秒的整数，优先使用 4–8 秒片段；不足 4 秒的末段保留少量相邻画面，合成时再精确裁回原时间线。
- 不以省调用次数为由合并多个具有不同物理结果的动作。每个“起始状态 → 触发 → 结束状态”动作独立成段并设置验收帧。
- 移除烧录字幕时，禁止使用与产品、手部、道具或关键动作相交的大范围 `delogo`、模糊条或拉伸补边。优先使用紧贴文字像素的时序遮罩、已确认无字幕母版或只修复字幕像素的局部方案。
- 需要模型只生成画面时，可为无音轨片段补兼容音轨以满足接口读取要求；最终仍合回原声。
- 选择 H3 原生台词时，按完整短句和换气点切段，把本段准确台词、声音表现和必要环境声直接写入 H3 视频提示词；不得在词语或音节中间切段，不得为声音调用第二个 API 或提交参考音频。
- 对移动、旋转或被遮挡的 Logo/产品，不能只做固定贴图；使用跟踪、遮罩、透视和遮挡处理。

## 结果保存与组装

- 记录 `segment_id`、时间码、模型、任务 ID、提交时间、状态、结果位置、失败原因和回退方式。
- 远程结果成功后立即下载本地副本，不把短期 URL 当作最终交付。
- 拼接前统一尺寸、帧率、像素格式、编码、色彩和时间基。直接无损拼接只在媒体参数完全一致时使用。
- 按原始时间线校准每段时长。原声回贴模式合回原片音轨；H3 原生台词模式默认保留同次生成的视频流和模型音轨，并统一采样率、声道、响度与环境底噪。只有用户明确同意解耦回退的无口型段，才使用锁定画面母版并只合入 H3 音轨。检查总时长、逐字台词、声音表现连续性、口型、动作音、节拍和转场点。

## 旧方案迁移说明

原始《通用视频元素替换流程与提示词模板》中的可灵 O1、Seedance、OSS 和示例代码只作为历史实现线索，不是默认路由，也不应视为永久有效的接口规范。只有用户明确指定旧供应商时，才先核对当前模型能力、官方参数、计费、隐私条款和返回结构，再使用对应实现。
