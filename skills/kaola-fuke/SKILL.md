# Kaola Fuke

把原视频当作唯一结构底片。成功标准是观众仍然认出同一条视频，只看到用户明确指定的元素发生变化。

## 先确定交付模式

根据用户动词选择模式：

- 用户说“分析、设计、给方案、写提示词”时，交付复刻执行包，不调用付费生成接口。
- 用户说“生成、制作、直接做、跑一下”且存在可用视频编辑工具时，先产出执行包，再逐段生成、回退、拼接和质检。
- 缺少兼容工具、账号或授权时，完成可执行到默认模型调用层的方案，明确唯一阻塞项；不要伪造任务 ID 或结果链接。

## 统一模型策略

- 凡需生成或编辑参考图、首帧、尾帧、遮罩底图或其他静态图像，默认使用可用的 `gpt-image-2-vip` 兼容图像能力，请求 4K。调用凭据必须由使用者通过其自身的环境变量或服务配置提供；不得读取、要求或记录他人的密钥。
- `gpt-image-2-vip` 必须传明确像素值而不是比例字符串：16:9 用 `3840x2160`，9:16 用 `2160x3840`；其他画幅使用接口文档列出的合法 4K 像素值。
- 凡需 AI 生成或编辑视频，默认使用 `MiniMax-H3`，通过 `dm-video-generate` 执行，并固定请求 `768P` 档；测试和正式成片都不自动升级到 `2K`。
- 抽帧、检测、切段、本地遮罩、跟踪、合成、转码和拼接不调用生成模型。
- 只有用户明确指定其他模型时才覆盖默认值。默认模型不可用时，说明阻塞；不要静默切换到可灵、Seedance 或其他模型。
- 在执行包和最终交付中写明实际图像模型、视频模型、模型原生分辨率与最终编码分辨率。

## 建立素材契约

开始前建立显式映射，不根据上传顺序猜用途：

```text
@视频1 = 结构底片
@图片1 = 人物 A 的新身份参考
@图片2 = 人物 A 的新服装参考
@图片3 = 新产品参考
```

至少取得：

1. 可访问的原视频。
2. “原元素 → 新元素”的替换映射。
3. 每个新元素的独立参考图；不要把脸、服装和产品拼成一张宫格。

多人镜头必须给人物分配稳定 ID，并确认替换谁。若无法从素材或上下文确定目标人物，先询问这一项，不要猜。

### 人脸确认门

只要原视频中出现可识别的人脸，在建立替换映射或调用任何生成、编辑接口之前，必须明确询问用户：是否要替换该人脸。多人视频要按人物 ID 逐一确认；不得因为用户只说“复刻视频”就默认保留或默认换脸。

默认询问话术：`原片中检测到可识别人脸。你希望：1）保留原脸；2）由你提供新的人脸参考图；3）由我生成一个身份不同的虚构成年人物参考图；4）模糊、遮挡或不展示人脸？` 多人视频必须为人物 A、人物 B 等分别询问并记录选择。

- 用户明确选择替换：继续确认新身份参考图，或在用户授权后生成一个身份不同的虚构成年人物参考；不得未经要求复刻原人物的精确身份。
- 用户明确选择保留：把该人物身份列入必须锁定项，不向不需要人脸参考的产品或手部片段传入人脸图。
- 用户选择模糊、遮挡或不展示：把它写成显式替换目标并采用对应局部处理方案。
- 用户已在当前请求中明确说明是否替换时，不重复询问，但仍要在任务摘要和素材映射中记录该决定。
- 未得到明确选择时，停在执行包之前，不调用付费模型，也不上传包含该人脸的本地素材。

### 字幕与声音默认策略

- 除非用户明确要求把字幕烧录进画面，所有新生成或编辑的视频仍默认提示“不生成字幕、逐词字幕、标题、角标、贴纸、水印或其他画面文字”，尽量降低模型自动出字幕的概率。
- H3 原生台词模式中，如果用户没有明确要求“必须无字幕”，模型仍自动生成字幕时不立即判失败：字幕必须与用户已确认台词逐字一致、语言正确、时间同步、样式稳定、不遮挡产品、人脸或关键动作，且没有随机文字、乱码、水印或额外宣传语；满足这些条件可以验收，但交付时必须说明成片含模型字幕。
- 用户明确要求无字幕、字幕留给后期或画面不能出现文字时，字幕属于硬性禁止项，任何自动字幕都判失败。原片已有烧录字幕时，把“移除烧录字幕并自然补全背景”列为显式编辑目标；不得一边保留字幕，一边声称已交付无字幕版。
- 自动字幕与已确认台词不一致、漏词、错词、重复、串入旧字幕，或遮挡产品与关键动作时，无论用户是否明确要求无字幕都判失败；优先只修问题段，不因字幕问题重跑完整视频。
- 台词与字幕分离：台词必须通过可听见的人声音轨朗读，字幕留给后期制作；不得用画面字幕替代声音，也不得因“无字幕”而静音或删除口播。
- 只要原片存在台词，而用户尚未指定声音处理方式，在调用付费生成前必须让用户选择：`1）原声回贴：生成后使用原片音轨；2）H3 原生台词：按原台词在生成视频时同步生成人声、口型与环境声。` 把选择记录在任务摘要、分段表和逐段生成包中。
- 用户未选择时默认停在执行包，不调用付费模型。原片没有台词时，按原片声音结构处理，不强行询问台词模式。
- 选择“原声回贴”时，模型输出只取画面，最终按原时间线合回原片声音。
- 选择“H3 原生台词”时，读取 [audio-modes.md](references/audio-modes.md)，先整理并确认带时间码台词，再按语义停顿分段，把每段准确台词、语言、说话人、声音表现、语气、节奏和口型要求直接写入 MiniMax-H3 视频提示词；只调用同一个 H3 视频生成 API，让视频模型在生成画面的同时原生生成人声、口型、环境声和动作声。最终保留 H3 返回的模型音轨，不再用原片人声覆盖。
- 选择 H3 原生台词时，默认目标是让同一次 H3 调用同时生成画面与声音，并保留模型返回的视频流和原生音轨；不得把“只取声音”冒充原生视听复刻。为维持画面控制力，必须以动作正确的视频为唯一底片，按单一关键动作切短，并把动作的起始状态、触发、运动轨迹、结果和切点写成逐时间约束。
- 无口型产品段经一次针对性短段重试后仍因台词条件重绘关键动作时，才可以把“锁定已通过画面、只取 H3 视频 API 原生音轨”作为可选回退告诉用户；必须得到用户明确同意后才能采用。用户要求继续验证模型原生视听控制力时，不得自行解耦画面与声音。
- 若底片带有烧录字幕，优先把未做模糊预处理的动作正确底片直接交给 H3，并把去字幕列为生成目标；字幕处理不得使用覆盖产品、手、道具或关键动作的大范围模糊带。
- H3 原生台词模式不得调用 TTS、音色合成、声音克隆、配音或其他独立音频 API，也不得为了生成声音传入 `reference-audio`。提示词中的“声音表现”只是给 H3 视频模型的表演描述，不代表调用音色服务。
- 若 H3 在一次针对性重试后仍漏词、改词、多人串音或口型明显不准，停止该段继续付费重试，报告问题并让用户选择回到原声回贴或暂不继续；不得自动调用独立配音或音色合成 API，不得静默替换声音路径，也不得声称模型已经准确朗读。

#### H3 原生台词生成前确认门

选择“H3 原生台词”后，每一次付费视频生成或重试之前，都必须先向用户展示本次实际提交的“声音确认单”，并取得明确确认。确认单至少包含：逐段时间码、说话人 ID、准确台词全文、语言与口音、说话人的性别表现与年龄感、音高与质感、语气、语速、停顿，以及本次是否修改了台词。用户只确认过旧版本时，任何字词、语言、说话人或声音表现的改动都视为新版本，必须重新确认。

- 语言默认取拉片或原片音轨识别出的源语言，不默认中文，也不默认英文；即使沿用源语言，仍必须把识别结果交给用户确认。原片是英文就先提议英文，原片是中文就先提议中文。无法可靠识别时明确标注不确定，不得猜测后直接生成。
- 说话人默认依据原片中实际说话人物、声音线索和已确认的替换人物参考共同推断。不得把“年轻女性”“成年男性”或任何人口特征写成通用默认值。原片可见男性且替换人物参考也是男性时，应先提议男性声音；原片人物与替换参考冲突、人物不可见或声音线索不足时，必须让用户决定。
- 拉片转写只作为待确认初稿。品牌、型号、数字、单位、专有名词和听不清的字词必须单列复核；未经用户确认的台词不得提交给 H3。
- 用户的明确确认必须覆盖“台词 + 语言 + 说话人表现”。仅回复“用模式 2”不等于确认这些内容；确认前停在提示词或执行包，不调用视频 API。

### 特效变更确认门

- 默认复刻原片特效、转场、光效、速度变化和动作声，不主动改造。用户明确要求修改特效时，该项成为允许改变项，不再视为必须锁定。
- 在付费生成前，必须按时间码给出“原特效 → 新特效”的变更表，并写清删除哪些重复效果、每种新效果只出现几次、强度、持续时间、与产品动作的因果关系、转场方式及对应声音。用户确认后才能提交。
- 不要用同一种光扫、粒子爆发、能量环、闪白或镜头震动反复证明多个卖点。优先让不同特效各自服务一个明确动作或卖点，并保留无特效的产品观察段，让节奏有层次。
- 任何已确认特效发生新增、删除、换位、重复次数或强度变化，都必须更新变更表并重新确认；不得在生成时临时发挥。

### 虚焦人脸问题修复流程（仅失败后触发）

- 不得在首次分析或首次生成时，仅凭抽帧主观判断某张脸属于“虚焦特殊镜头”并主动进入本流程。首次仍按普通复刻分段和正常的人脸、产品替换方案执行。
- 只有满足以下任一条件才触发本流程：1）生成后质检明确发现背景人脸没有替换、仍残留原身份或融合失败；2）用户明确反馈该片段存在虚焦人脸、身份残留、贴脸感或希望改为产品聚焦展示。
- 触发后，如果人物在产品后方、镜头对焦前景产品，导致背景人脸失焦、被产品遮挡或只露出部分五官，不得使用本地贴脸、硬边蒙版、马赛克或简单模糊冒充换脸；这类处理无法匹配景深、遮挡和头部运动。
- 默认先走图片方案，不直接把这类镜头交给视频模型换脸：从原片选择最能代表构图和产品展示姿态的帧，把原始帧、新人物参考图和产品参考图交给图像编辑模型，先生成一张“产品锐利清晰、新人物身份正确但整张脸自然虚焦、无字幕”的替换画面。
- 图片构图必须优先展示产品、提高产品存在感和结构清晰度，把人脸降为不抢视线的背景元素。可以让产品、浅景深或构图自然挡住部分脸部，但不得残留可识别的原脸，也不得出现马赛克观感。
- 替换图通过质检后，再把该图交给图生视频模型。视频提示词必须具体描述原镜头的运镜和动作，包括推近或拉远、横移或摇镜、产品移动方向、旋转角度、手指操作、遮挡变化、动作节奏和镜头时长；不得只写“让图片动起来”。
- 图生视频阶段继续锁定：产品始终是唯一清晰焦点；背景新人物的脸全程保持一致的自然浅景深虚焦；不得突然对焦人脸、补出清晰五官、改变身份、生成口型特写或新增展示动作。
- 若原镜头动作很弱，可只做轻微推拉、呼吸式手持位移或产品小角度转动；若图生视频会破坏产品结构，直接使用替换图做确定性轻推拉，不再反复付费重试。
- 若用户允许完全不露出脸，可把构图裁到产品与手部，或让产品遮住人物脸部；此时仍不得保留可识别的原脸残片。
- 质检必须同时满足：新身份无原脸残留；脸部虚焦来自一致景深而不是马赛克；产品始终清晰且结构稳定；运镜和动作符合提示词；手指与产品遮挡正确；画面无字幕和随机文字。

默认沿用原视频的画幅、帧率、时长、镜头顺序与原声。只要存在 H3 生成片段，默认把整片统一到 H3 的 `768P` 输出档；若全片仅保留原片或做本地确定性合成，则保持原分辨率。把用户指定的不可改区域、允许改变项和输出规格一并写进任务摘要，不要把 768P 输出无依据地放大后冒充原生高分辨率。

输入来自 `kaola-lapian` 的 `route-fuke.md` 时，把它作为结构分析底稿，并继续以其中映射的 `source.mp4` 为唯一结构底片。实际复核原视频后才能采用镜头切点、动作与遮挡描述；拉片不能替代原视频。若拉片尚未包含“原元素 → 新元素”映射，先向用户补齐该映射和对应参考图，再生成复刻执行包。

## 遵守硬性不变量

- 保持镜头数量、顺序、起止时间、构图、机位、镜头运动、场景和剪辑节奏。
- 保持每镜人物数量、站位、动作、表情方向、手势以及物体的数量、位置、角度和遮挡关系。
- 把具有因果关系的微动作写成逐状态的“关键动作不变量”，例如“纸仍在键盘上 → 风口对准 → 纸被气流抬起 → 纸离开键盘”。最终画面必须保留完整状态顺序、发生时点和运动方向；只写“吹键盘”不算完成动作锁定。
- 只改变替换映射中列出的属性；不要顺便美化、改剧情或新增展示镜头。
- 原镜头没有人物时，不得新增人物；只有手和产品时，不得扩写成真人展示。
- 只把与当前片段有关的参考图传给模型，避免身份、服装或产品参考互相污染。
- 声音严格遵循用户已选择的“原声回贴”或“H3 原生台词”模式；无论选择哪一种，都默认不把台词烧录成画面字幕。
- H3 原生台词的准确文字、语言和说话人表现必须是用户刚刚确认的版本；特效存在显式改动时，只允许实现已确认的特效变更表。
- 不承诺“逐帧完全一致”。把目标表述为最大限度保留结构，并设置局部回退方案。

## 执行工作流

### 1. 检查原片

实际读取视频，不凭剧情描述或记忆写方案。检查时长、分辨率、画幅、帧率、编码、音轨和可访问性。

提取镜头切点和带时间码的抽帧：全片至少约每秒一帧；在开头、结尾、人物交互、遮挡、手部操作和产品特写处加密。若当前工具无法读取视频，停止在分镜前并请求可访问文件或直链。

### 2. 建立分段表

按镜头角色而非固定秒数分段。逐段记录：时间码、镜头类型、人物/物体、动作、替换目标、必须锁定项、遮挡难点和处理方式。

分段还必须服从关键动作边界。一个具有明确起因和结果的动作单独成段，不得为了减少调用次数把配件安装、吹走纸张、换喷嘴等多个动作合并成一个长生成任务。每段记录动作的起始状态、中间触发、结束状态和参照物。

读取 [shot-strategy.md](references/shot-strategy.md)，使用其中的镜头分类、决策矩阵和分段表模板。

### 3. 为每段选择最小改动方案

按以下优先级选择：

1. 不含目标元素：保留原片。
2. 固定角标、Logo 或贴片：使用小范围本地覆盖。
3. 移动、旋转或被遮挡的小元素：使用跟踪、遮罩和合成。
4. 人脸、服装或主体产品确实需要随动作变化：默认使用 `MiniMax-H3` 的 `768P` 档处理底片视频。
5. H3 原生台词：默认保留同一次 H3 生成的画面与声音；按单一关键动作切短并使用逐时间状态链控制。一次针对性短段重试仍失败时，停止付费重试并向用户提供回退选择。
6. 用户在失败后明确选择视听解耦回退：无口型段锁定已通过画面，只取 H3 视频 API 的新音轨；未选择时不得使用。
7. 生成质检失败或用户明确反馈虚焦人脸、原身份残留时：才进入“虚焦人脸问题修复流程”，先生成产品聚焦替换图，再按原镜头运镜和动作做图生视频。
8. 模型持续重绘镜头：缩短片段、减少参考图；仍失败则回退原片或局部合成。

不要把不同镜头类型塞进一个长片段，也不要为“不需要变化”的片段调用模型。

### 4. 生成逐段提示词

读取 [prompt-templates.md](references/prompt-templates.md)。把“全局不变量 + 当前片段目标 + 镜头专用约束 + 禁止项”组合为每段独立提示词。

每段同时列出：

- 输入底片片段。
- 本段需要的参考素材 ID。
- 正向提示词。
- 负面约束。
- 声音模式、说话人、带时间码台词、声音表现描述与是否保留模型音轨。
- 画面/声音耦合方式：默认 `H3 原生视听＝保留同次生成的画面＋音轨`；仅在一次短段重试失败且用户明确同意后，才可标记 `解耦回退＝锁定画面母版＋仅取 H3 音轨`。
- 关键动作状态链及其抽帧验收点。
- 台词、语言、说话人表现和特效变更的用户确认状态；任一项为“待确认”时不得进入付费生成。
- 建议处理方式与回退方式。

除非用户明确要求画面字幕，每段提示词都要加入“无字幕、无逐词字幕、无标题、无水印、无其他画面文字”，尽量控制模型不自动出字。声音栏必须明确写“原声回贴”或“H3 原生台词”；选择后者时使用 [prompt-templates.md](references/prompt-templates.md) 的原生台词模板，不能用字幕替代台词音轨。若用户没有把无字幕设为硬要求，H3 最终生成的准确同步字幕可按上述容错规则验收。

### 5. 生成与组装

仅在用户明确要求制作时执行外部生成。H3 原生台词模式还必须确认当前版本的准确台词、源语言默认值和说话人表现；存在特效改动时还必须确认特效变更表。需要静态图像时用 `gpt-image-2-vip` 的 4K 档；需要视频时用 `MiniMax-H3` 的 `768P` 档。优先短段测试最难镜头，再决定是否批量处理。付费调用前读取 [safety-and-execution.md](references/safety-and-execution.md)。如需使用其他服务，先由使用者自行完成该服务的账号、授权与凭据配置，并核对当前接口。

生成后立即保存本地副本，记录片段、任务 ID、状态、模型和失败原因。只重跑失败段；不要因一个镜头失败而重跑整片。

统一片段的尺寸、帧率、编码和时长，再按原顺序拼接。原声回贴模式合入原片音轨；H3 原生台词模式默认保留并统一同一次生成的视频流与模型音轨，不得重新覆盖为原人声。只有用户明确同意解耦回退的无口型段，才使用已锁定画面母版并只合入 H3 返回的音轨。两种模式都检查音画同步、台词完整性、总时长漂移。字幕按用户要求分级验收：明确要求无字幕时必须零字幕；未明确要求时，只有与确认台词准确同步且不遮挡主体的模型字幕可以通过。

### 6. 对照质检

逐段并排对照原片和最近一次用户认可的画面母版，不只看首尾帧。按 [shot-strategy.md](references/shot-strategy.md) 的质检清单检查人物数量、动作、构图、产品位置、遮挡、镜头顺序、时长、Logo 和音画同步。对关键动作按至少 4 fps 加密抽帧，逐项核对“起始状态 → 触发 → 结束状态”；任一状态缺失都判定失败，即使台词、产品和场景正确也不能通过。

把问题定位到具体片段，按“重试当前段 → 缩短当前段 → 减少参考 → 局部合成 → 回退原片”的顺序修复。

## 固定输出结构

按下列顺序交付；没有执行生成时省略第 6 项，不省略其余项目：

1. **任务摘要与假设**：目标、输出规格、允许改变项、必须锁定项。
2. **素材映射**：每个素材 ID 的角色及其对应目标。
3. **替换映射**：原元素、新元素、涉及人物或镜头、参考图。
4. **带时间码的分段表**：镜头类型、处理方式、理由、风险和回退。
5. **逐段生成包**：每段引用素材、提示词、负面约束、`gpt-image-2-vip 4K`/`MiniMax-H3` 路由和 `768P` 参数建议。
6. **执行记录与成片**：状态、任务 ID、实际模型、原生与最终分辨率、本地文件或结果链接、失败回退记录。
7. **质检报告**：通过项、问题片段、修复结果、声音模式、台词与口型检查、仍存限制。

不要只交付一条整片提示词；这类任务的核心交付物是可追踪的逐段执行包。

## 权利与安全边界

不要把 API key、访问令牌或私密素材链接写入 Skill、提示词、日志或交付文档。

## 路由边界

- 若任务不要求保留某条原视频结构，而是把防水、降噪、缓震等功能从零设计成发布会式演示，改用 `kaola-maidian`。
- 若任务是从商品图和卖点设计销售转化视频，改用 `kaola-daihuo`，本 Skill 不代做其规范。
- 若同一项目既要替换原片又要新增卖点镜头，拆成两个片段流程：原片段按本 Skill，新插入段按 `kaola-maidian`，最后再做统一成片计划。
