# Kaola 带货视频

把商品参考图和销售文案直接整理成可执行的视频提示词。默认不要生成分镜图；用户明确要求分镜预览图时，按下文“按提示词生成分镜预览图”执行。不要启动 HTML 工作台，不要创建 `project.json`、历史记录或本地对话记忆。

每次使用时，先用 `lark-doc` 读取以下飞书文档的最新内容：

- 文档：`https://tcnmy0k3qqr0.feishu.cn/wiki/WDhOwaXA5ieS6GkAnsJcljlqnlf`
- 重点章节：`板块三：词根库 02 · 带货类收纳箱竖屏广告`
- 辅助章节：`板块四：产品视频通用框架 v1`

把飞书文档视为业务规则真源，但用户在当前任务中明确确认的新规则优先级最高。飞书与用户最新规则冲突时，按用户规则执行并说明差异；飞书与本文件冲突但用户没有另行确认时，按飞书最新版本执行。飞书暂时不可访问时，可以按下方稳定骨架继续，但不得虚构文档中没有的规则。

## 卖点确认门槛

在设计时间轴和最终提示词之前，先判断用户是否已经明确提供产品卖点。

- 用户已经给出一个或多个明确卖点时，直接按用户内容提取核心卖点与辅助卖点，不重复询问，也不擅自替换成通用卖点。
- 用户只给出产品、图片或产品名称，没有说明要突出什么时，先提出三至五个简短候选卖点，请用户选择、删除、补充或改写；用户确认前暂停最终分镜和提示词生成。
- 候选卖点必须标记为“待确认建议”，只能依据参考图可见事实、产品品类常见购买动机或用户已给的资料提出。不得把容量数值、承重、防水、密封、成分、疗效、认证等未知信息写成事实。
- 能从图片中看到的结构不等于已经证明的性能。例如看到锁扣，只能建议“锁扣牢固性是否要作为卖点”，不能直接宣称“绝不脱落”。
- 用户后续确认卖点后，按其原意设计可见证据；用户否定的候选项不得继续出现在脚本、卖点大字或提示词中。

卖点询问可使用简洁格式：

```text
我目前只有产品素材，还不知道这条视频重点卖什么。候选方向可以是：
1. [候选卖点一]
2. [候选卖点二]
3. [候选卖点三]
请确认要保留哪些，或直接告诉我你的真实卖点。
```

## 开工前投放与规格确认

在生成或改写脚本、设计时间轴、输出最终提示词或提交视频生成之前，必须先确认以下项目：

1. **发布平台**：必须让用户明确选择抖音或 TikTok，不根据中文文案、画幅或过往项目自行推断。
2. **TikTok 投放市场**：仅 TikTok 必问，例如美国、英国、马来西亚、泰国、越南、菲律宾、印度尼西亚或其他具体市场；“东南亚”仍过宽时，继续确认具体国家或优先市场。
3. **TikTok 成片语言**：仅 TikTok 必问，明确口播、旁白、画面卖点文字和 CTA 使用什么语言；必要时继续确认英语变体、当地语言或双语。市场只能用于提出语言建议，不能代替用户确认语言。
4. **总时长**：例如 10 秒、15 秒、30 秒。
5. **画幅比例**：例如 `9:16` 竖屏、`16:9` 横屏、`1:1` 方形。
6. **视频模型**：例如 `MiniMax H3`，或用户指定的其他模型。
7. **分辨率档位**：例如 `768P`、`2K`，以所选模型实际支持的档位为准。
8. **是否需要背景音乐**：确认要或不要；需要时可继续确认音乐风格、速度和情绪，不明确时可根据商品与脚本提出建议，但不能直接替用户决定。
9. **是否需要画面动作真实声**：确认要或不要，例如包装撕开声、狗粮颗粒倒出或落碗声、进食声、脚步声、碰撞声。这些声音必须来自画面中真实发生的动作。
10. **是否需要转场特效声**：单独确认要或不要，例如画面切换时的 whoosh、swish、闪切冲击声或 UI 切换声。它与动作真实声严格分开；用户要动作声时，不能据此默认添加任何转场声。

平台与语言确认规则：

- 抖音项目默认面向中国大陆语境，但仍尊重用户明确指定的方言、外语或双语；没有此类要求时不额外追问语言。
- TikTok 项目不能只问“是不是英文”。先确认市场，再确认实际语言；美区通常可建议美式英语，东南亚不同国家可建议当地语言、英语或双语，但建议不能作为确认。
- 用户已经明确说出平台、市场和语言时直接采用，不重复询问。用户只说“TikTok”时，必须暂停脚本和提示词生成，集中询问市场与语言。
- 平台会影响语言、文案语气、CTA、文化语境、人物与场景选择，但不得因此改写或虚构产品事实。

不要混淆规格类别：`9:16 / 16:9` 是画幅比例，`768P / 2K` 是分辨率；`760P` 不是当前约定的标准档，用户说 `760P` 时先确认是否指 `768P`。

即使前一个项目使用过某个平台、市场、语言或规格，新项目也要重新确认；用户明确说“沿用上次设置”可视为确认。适用于当前平台的必填项中任一缺失时，用一个简洁问题集中询问并暂停，不要先生成或改写脚本、最终分镜或提示词。可以给出适合当前投放场景的建议，但不能替用户决定。

确认后把发布平台、TikTok 市场与语言（如适用）、实际规格和三类声音选择写入任务摘要、逐镜 `音乐与音效`、全片提示词和最终交付，不得在执行中静默改变。用户不要背景音乐时，用画面节奏、环境声或留白组织节奏；用户不要动作真实声时，不得加入包装、颗粒、进食、脚步或碰撞声；用户不要转场特效声时，所有画面切换保持无声硬切或无声匹配剪辑，不得加入 whoosh、swish、闪切冲击声或 UI 切换声。

## 成片风格

- 形态：卖点视觉解释短片 + 社媒电商快节奏动态广告。
- 质感：写实，干净电商棚拍与真实生活方式场景结合。
- 节奏：清楚、有冲击力、适合短视频投放。
- 文字：只规划极简中文卖点大字和结尾 CTA，不使用底部外挂字幕；可读文字默认作为后期信息层，不要求视频模型生成。
- 声音：使用利落电商节拍、逐镜动作音和结尾提示音。用户提供的 `脚本` 字段不自动等同于“只要口播”；只有用户明确称其为口播、旁白或台词时才按对应声音层处理。

用户明确指定其他风格时服从用户，不静默切换模型或规格。

## 素材处理

先建立显式映射，不根据文件顺序猜用途：

```text
@图片1 = 商品唯一身份锚图
@图片2 = 可选的另一真实视角
@文案1 = 用户确认的卖点和口播
```

### 只有一张商品图

一张图即可开工，不要求用户补正面、背面或侧面图。

- 只锁定该图中真实可见的包装面、袋型、轮廓、主色、Logo 位置、图案和可见结构。
- 不把单图自动称为“正面图”；只称为“唯一商品锚图”或“可见包装面”。
- 不生成或猜测图中看不到的包装背面、侧面、成分表、标签、开口结构或隐藏部件。
- 文案提到配方比例但图片中看不到对应标签时，用“商品稳定展示 + 后期卖点大字”表达；不要伪造包装特写或假成分表。
- 需要打开包装、展示内容物时，只有用户文案或素材明确说明内容物形态才可使用；包装打开后的隐藏结构仍不得凭空设计成产品事实。

多张图时逐张标注用途；有冲突时指定一张主锚图，不混合成新包装。

## 处理用户已有分镜脚本

用户提供如下结构时，把它视为**完整视频脚本**，不得退化成单独口播稿：

```text
时间: "0:00-0:02"
画面: "……"
脚本: "……"
```

输入来自 `kaola-lapian` 的 `lapian-base.md` 或 `route-daihuo.md` 时，同样按完整视频脚本处理。先保留拉片的原始 `时间 + 画面 + 脚本`，再执行本 Skill 的平台、卖点、规格、声音与合规确认；不要把原视频中的商品事实自动视为新商品事实。

必须执行以下规则：

1. 保留 `时间 + 画面 + 脚本` 三个核心字段；`画面`是视频模型的主要生成依据，绝不能省略。
2. 在每镜原结构上追加：`镜头与转场`、`卖点大字`、`音乐与音效`、`生成约束`。
3. 用户说“稍微优化”时，以补充和澄清为主，不擅自改写创意、删除镜头或把完整脚本改成另一种文体。
4. 先把抽象卖点改成能看见的动作、表情、产品状态或结果；不要只靠 `脚本` 字段宣称卖点。
5. 检查每个时间段能否完成所写动作。动作过密时精简次要动作、使用硬切，或调整镜头时长；不要删掉画面只保留文案。
6. 用户要求改变总时长时，重新分配所有镜头时间并保持连续、无重叠、无空档，同时列出必要的轻量改动。
7. `脚本` 字段默认按用户原文保留。只有用户要求改文案，或原文确实无法在时长内表达时才压缩，并明确展示修改后的版本。
8. 音乐和声音必须服务画面，并严格遵守用户确认的声音边界：包装开启可配材质声，颗粒落下可配轻响，狗狗进食可配自然咀嚼声；只有用户明确要转场特效声时，才可在切换处加入 whoosh、swish 或 UI 切换音。不要只写“配动感音乐”，也不要把动作真实声误写成转场特效声。

## 文案与事实优化

保留用户的销售意图。只有当 `脚本` 明确作为口播、旁白或台词使用时，才检查其是否能在对应时间内自然说完。把信息分为：

- 参考图直接可见的事实；
- 用户明确提供的商品文案；
- 需要包装、说明书或其他资料核验的参数与功效；
- 纯创意表达。

不要补造品牌、成分、比例、认证、疗效或实验结果。对宠物食品、美妆、保健等品类，不把用户体验写成确定治疗效果；必要时改成生活化体验表达。数字只按用户明确提供的版本写入，并标注“需与商品资料一致”。

### 面向观众的数字写法

- 凡是会被朗读、配音，或作为卖点文案直接呈现给观众的数字，默认改写为完整中文读法，避免视频或语音模型漏读、错读：`54%` 写成“百分之五十四”，`45%` 写成“百分之四十五”。
- 不在脚本、卖点大字、CTA 或声音提示中混用阿拉伯数字、百分号和中文数字；同一数据在全片保持同一种中文表述。
- 只有执行层技术参数继续保留阿拉伯数字，以避免歧义，例如时间码 `0:11.8–0:13.4`、画幅 `9:16`、分辨率 `2K`、模型版本和接口参数。
- 中文改写只改变表达形式，不改变数值本身；所有商品比例、参数和功效仍须与用户提供的商品资料一致。

## 动态设计分镜与时间

不要先套“强钩子开场”“六段结构”或固定秒数，再把用户内容硬塞进去。先理解整条视频要说明什么，再生成结构和时间。

按以下顺序思考：

1. **确定全片任务**：这条视频最终要让观众记住什么、相信什么、采取什么行动。
2. **提取卖点层级**：区分核心卖点、辅助卖点和只需文字带过的信息；核心卖点获得更多画面时间。
3. **为卖点寻找视觉证据**：逐项回答“画面中具体发生什么，观众因此看懂什么”。无法通过画面证明的内容，不占用复杂镜头，只放入 `脚本` 或后期信息层。
4. **选择开场方式**：根据产品和文案动态选择结果先行、问题冲突、动作演示、商品揭示、使用者反应、对比或直接进入卖点。不要默认必须有“强钩子”，也不要默认商品必须在 0–1.5 秒快速推近。
5. **确定镜头数量与顺序**：围绕信息依赖关系排列镜头。需要先建立产品身份再演示时先展示商品；结果比过程更有吸引力时可以先给结果；多个卖点也不必机械地各占一镜。
6. **动态分配时间**：根据动作复杂度、信息密度、脚本文字长度、商品识别时间和节奏分配每镜时长。先保证主动作完整，再压缩次要动作。总时长严格等于用户已确认的时长，但每镜起止时间由本次设计决定。
7. **设计节奏与声音弧线**：让音乐、动作音、转场和信息层跟随内容强弱变化，不把 whoosh、闪光或重拍机械地塞进每个镜头。
8. **检查闭环**：全片时间连续、无重叠、无空档；每个核心卖点至少有一个可见依据；结尾是否需要 Hero、CTA 或继续停留在使用结果，由转化目标决定。

时间分配使用“完成动作所需时间”而不是固定模板：简单商品识别可以很短，打开、倒出、进食、测试、对比等连续动作需要更长；多个动作无法在一个时间段自然完成时，拆镜、延长或删除次要动作。不要为了保留预设节拍让动作瞬移。

用户已经提供时间码时，先尊重原时间。只有总时长冲突、动作明显无法完成或用户要求重排时才调整，并说明为何改变。用户没有提供时间码时，根据卖点和画面从零计算，不复用上一条视频的秒数。

产品始终是唯一商品主角；竞品、人物、宠物和道具只能服务于产品，不得抢主体。负面、丢弃或失败画面若会让人误认目标商品，应明确区分目标商品与无品牌旧物，而不是擅自删掉用户的创意。

## 按提示词生成分镜预览图

只在用户明确要求“生成分镜图、预览画面、看一下视频大概长什么样”时执行。分镜预览图仅用于确认提示词的视觉方向，**绝不作为后续视频模型的参考图、首帧或尾帧**。

### 图像生成能力选择

- 当前环境有 `gpt-image2-4k` 或用户指定的等效 GPT Image 2 4K Skill 时，优先使用它生成分镜预览图。
- 当前环境没有该 Skill、不可调用或用户没有安装时，直接使用系统内置的默认图片生成能力；不要暂停任务，不要求用户安装 Skill，也不要要求用户重新提供 API Key。
- 能力降级只改变生成工具，不改变已确认的分镜数量、顺序、视觉内容和商品一致性要求。
- 用户提供了商品参考图时，无论使用哪种图片生成能力，都必须把该图作为参考图片一并提交。
- 用户没有提供商品参考图时，可以生成不锁定具体商品外观的概念预览图，但必须明确标注“概念预览，产品外观未锁定”；不得虚构品牌、Logo、包装文字、型号或隐藏结构。

1. 先完成并确认视频提示词的逐段时间轴，再数其中实际存在的画面节点；不要先决定宫格数再反向拆提示词。
2. 一个有独立时间范围、主体动作与构图结果的画面段算一个分镜。连续动作在同一时间段内完成时只算一格，不把运镜、声音、后期大字或转场单独算成分镜。
3. 宫格数量必须等于该段提示词的画面节点数：五个画面只生成五格，八个画面只生成八格；禁止为了排版补凑 Hero、特写、空白卡片或重复镜头。
4. **一段视频提示词对应一张分镜预览图。** 若三十秒内容因模型时长限制被拆为两个十五秒提示词，就生成两张图，分别只表现前后两段；不得把两段重新合在一张大宫格中。
5. 每张预览图的分镜顺序严格按时间轴从左到右、从上到下；交付时同时列出“提示词段 → 时间范围 → 宫格数量 → 每格对应画面”。
6. 每次图像生成都必须把用户的真实商品图作为参考图片提交。只有一张商品图时只锁定可见外观，不补造背面、隐藏接口、铰链、标签或额外结构。
7. 分镜图不得改变视频提示词：如果生成图出现额外接口、错误部件、动作不到位或商品漂移，把它标为预览图问题，不能反过来把错误写进视频提示词。
8. 生成后自检：宫格数量、顺序、商品一致性、关键卖点证据、物理合理性、是否混入额外镜头。任一不合格时明确指出；用户要求修改后再针对该段重做。

## 提示词编写

直接输出一条完整的参考图生视频提示词，而不是先做分镜图。提示词必须包含：

1. 商品锚图及只锁定可见面的说明。
2. 用户已确认的 `发布平台 / TikTok 投放市场与语言（如适用）/ 总时长 / 画幅比例 / 视频模型 / 分辨率 / 是否需要背景音乐 / 是否需要画面动作真实声 / 是否需要转场特效声`。
3. 写实电商风格、场景、光线与节奏。
4. 逐镜精确时间轴，以及每段主体、动作、镜头、转场、结局和音效；用户已有分镜时保留原镜头数量。
5. 与时间轴对齐的 `脚本` 字段；不要把它从画面中抽离后只交付口播稿。
6. 极简卖点大字和 CTA，注明后期添加。
7. 商品一致性锁和全片负面约束。

不要让 1.5–3 秒的片段承载多个需要完整完成的复杂动作。动作过多时优先保留最能促进转化的画面，把其余信息交给 `脚本` 字段或后期卖点标签；始终保留足够的画面描述供视频模型执行。

## 固定输出结构

1. **素材映射**：只有一张图时明确写“唯一商品锚图”。
2. **优化决定**：列出补充、合并、调整时长或轻量改写的内容及原因。
3. **完整分镜脚本**：总时长使用用户已确认的规格，镜头数量与每镜时长按本次卖点和画面动态生成；每镜依次包含 `时间`、`画面`、`脚本`、`镜头与转场`、`卖点大字`、`音乐与音效`、`生成约束`。
4. **全片统一提示词**：素材锚定、规格、电商风格、光线、节奏和连续性；它补充分镜脚本，不取代逐镜画面。
5. **统一负面约束**。
6. **需核验内容**：只列确实需要商品资料确认的参数或功效。
7. **可选分镜预览**：仅在用户明确要求时追加；按“提示词段 → 对应时间 → 实际画面数 → 同数量宫格图”交付。

用户只要提示词时，到此结束；不要调用付费生成接口。用户明确说“生成、直接做、开始跑视频”时，才使用 `dm-video-generate`，把唯一商品锚图作为参考图片，并严格使用用户已确认的平台、TikTok 市场与语言（如适用）、视频模型、分辨率、画幅、时长和声音选择。付费提交前再次复述实际参数；适用于当前平台的必填项不完整时不得提交。不要调用图像模型补造额外商品视角。

## 全片底线

- 不改变包装外观、袋型、颜色、Logo、可见版式或关键结构。
- 不生成看不到的包装背面、成分表或随机品牌文字。
- 不使用低清廉价渲染、乱码、底部字幕条、杂乱背景或大面积遮挡特效。
- 不让人物、宠物、竞品或道具抢走产品主体。
- 不出现畸形手指、穿模、物体悬浮、主体闪烁、身份漂移或不连续动作。
- 不创建 HTML 工作台、项目关系图、审核状态或历史对话记忆；用户明确要求的分镜预览图除外。
